# Proposed substantial follow-up release (#112)

Proposed version: **0.15.0**, subject to maintainer acceptance. This is a scope
proposal, not a release authorization or receipt. No version, tag, frozen schema,
release plan, build, upload or public artifact is changed by this document.
Published 0.14.0 and schema 0.3.13 remain immutable.

The release would consolidate post-0.14.0 SQLite lifetime integrity, comparative
genomic/coverage and historical-selector corrections, declared refresh request
restoration, source observation/prerequisite handling, versioned disease identity
coverage, comparative operation observation, persisted original results/credit,
verified bibliography and compact operation `@2` with historical `@1` reading.
The [public scientific dossier](scientific_dossier.md) adds a bounded review
using existing APIs, with retained units, original support and explicit unknowns.
The [latest source receipt](scientific_dossier_checkpoint.json)
qualifies `6e35c1d` with CI 15/15 and governance 1/1; it does not qualify a future
versioned release candidate or installed release artifact.

The [MOLI receiving PR #67](https://github.com/uibcdf/moli/pull/67) exercises the
qualified producer with public Recorda 0.3.0 and Ackredit 0.9.0. It is consumer-owned
review material, with broader contracts and scientific acceptance still open.
Recorda is not added as a Sabueso runtime dependency.

Follow the authoritative [staged release route](../../devtools/conda-build/README.md):

1. Confirm the substantial release scope and version, historical readers, source
   delivery and dependency release preflight. Choose the final candidate and verify
   all applicable CI/governance gates on that exact SHA.
2. Build one immutable staging artifact. Qualify clean installed-package receiving
   on Linux, Apple Silicon macOS and Windows, each with Python 3.11–3.14 and declared
   public dependency provenance. A local editable suite is a separate scope.
3. Freeze the currently unpublished card schema 0.3.14 using the exact candidate's
   installed package and declared public fixtures. Preserve earlier cards/shapes;
   migration, refresh and historical selectors retain their declared meaning.
4. After candidate acceptance, publish the release, promote that same tested Conda
   file, verify a clean public installation and complete identical-tag Zenodo
   archival. Update installation/release claims only after their evidence exists.

[Consumer usefulness](consumer_scientific_acceptance.md) remains explicit and
separate from package admission. No private pilot material or new aggregates enter
this proposal. Releases remain few and substantial; this scope groups the completed
integrity and traceability work into one delivery instead of many small releases.
